# Accessibility Report

MkDocs Material provides keyboard navigation, responsive layouts, contrast-aware light/dark palettes, semantic navigation, focus states, and accessible search. Custom SVG assets include a title where rendered as content, and the responsive table wrapper preserves table semantics.

CI verifies build integrity. A hosted release should additionally run automated WCAG checks and manual keyboard/screen-reader review against the deployed URL.

## Provider Platform Preview

The `v1.4.0` loopback provider console uses semantic headings, labelled masked credential fields, native buttons and selects, visible keyboard focus, responsive layout, text labels beside every status color, and confirmation before a provider health request can transmit data. The provider key manager groups slot controls with programmatic labels, exposes active and recovery state as text, requires selecting a visible replacement slot before active-key quarantine, and clears masked fields after submission; it never renders credential values. Model controls use labelled native input or select elements, including a locally discovered Ollama list. Sidebar navigation uses buttons and scrolls to live sections; the theme switch exposes state through `aria-pressed`, respects a system dark-mode preference initially, and stores only the chosen theme locally in the browser. The new Agent command center exposes host adapter status and a read-only copilot planner with labelled objective/provider controls; Runs and workflows presents bounded progress metadata with an explicit message that execution remains on the governed CLI path. The dashboard does not expose a direct workflow execution control. The session token is removed from the address bar after startup; the UI never renders credential values or raw provider payloads. The console is validated by `test/dashboard.test.js` for its protected shell, separate script asset, consented test request, headers, key-slot lifecycle, model persistence, agent/workflow metadata boundaries, plan-only surface, and API boundary.

Release promotion still requires hosted keyboard-only, screen-reader, 200% zoom, contrast, and automated WCAG evidence against the released provider view. Any future screenshot must be declared through `docs/assets/visual-evidence.json` with alt text, source dependencies, version, review date, and content hash.
